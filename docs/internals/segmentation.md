# Segmentation

Grapheme, word and sentence boundaries (UAX #29), line break opportunities (UAX #14) and script runs are iterators over caller-owned state that take text in pieces. This page explains the engine they share and the traps in it.

## One iterator type

UAX #29 defines three segmentations of the same shape: walk the text and decide, before each code point, whether a boundary falls there. Line breaking has the same shape with one more answer, a mandatory break. Three or four iterator types with their own feed and next functions would multiply the API for no difference a caller can use, so there is one public type, `muniSegmentIterator`, with an init function per kind and shared `muniSegmentIterator_Feed` and `muniSegmentIterator_NextBreak`.

The public struct is opaque storage. [`src/segment.c`](../../src/segment.c) copies the internal `muniSegmenter` in and out of it with `memcpy`, which keeps every access within the C aliasing rules, and dispatches on the kind once per boundary, not per code point.

The caller holds that storage, so every call checks what it copied out before it reads it, as the family's rule on state a caller holds asks ([maul-conventions.md](maul-conventions.md)): the cookie an init call writes in the cursor, every count against the storage it counts (the cursor's pending bytes and position, the override count), every class, state and hold kind against the values its rule set writes, and every flag's byte as a 0 or 1 before the copy is read as a `bool`. It also checks what the assertions downstream rely on: a waiting cursor holds less than a code point, and a hold lies before the cursor; and that an SA run starts at or before the cursor, so the offset the caller's breaker is asked about lies inside the run, as `segment.h` promises. An iterator no init call set up is refused with `muni_errorInvalid`, so no bit pattern makes a call read outside the state; the pointers it keeps (the text, the overrides, the caller's breaker) cannot be checked, and one forged there is outside the contract. The script iterator ([`src/script_runs.c`](../../src/script_runs.c)) checks its state the same way. The checks run once per call, not per code point. They are inlined into each call (`MUNI_ALWAYS_INLINE`), since the compiler left them outlined at 1 to 2 ns more per call, and they read the flags' bytes from the caller's iterator rather than from the copy just made of it, so that no load waits on the copy's stores. On the bench, where every call reports one boundary, they cost a grapheme break about 2 ns (11%) and a line break about 5 ns (20%), all of it instructions executed: they add no branch or cache miss. `test/fuzz_iterators.c` sets every byte outside those pointers, the lengths and counts that go with them, and the kind of an iterator with overrides, which says where their count is, from its input and calls every function again, with a breaker that traps on an offset outside its run.

Its size follows the state: a `static_assert` in [`src/segmenter.h`](../../src/segmenter.h) keeps `muniSegmenter` within it, so a change that grows the state fails to build until the public iterator grows with it, and on 64-bit targets a second one keeps the iterator from growing a whole `uint64_t` more than the state needs. On 64-bit targets `muniSegmenter` fills all 128 bytes, with the cookie in the two bytes that were the cursor's padding, a line iterator's strictness and writing system packed in the byte after the hold's kind and the class overrides' pointer in the last 8. The next switch or piece of state therefore grows the public iterator, which changes the ABI; from 1.0.0 that is allowed in a minor release, so its pull request is a `feat` with no `!`.

## The engine and its holds

[`src/segmenter.h`](../../src/segmenter.h) walks the text and asks a rule set about each code point: break, mandatory break, join, or hold. The engine is a `static inline` function that takes the rules as function arguments, and each rule file ([`grapheme.c`](../../src/grapheme.c), [`word.c`](../../src/word.c), [`sentence.c`](../../src/sentence.c), [`line.c`](../../src/line.c), [`line_tailored.c`](../../src/line_tailored.c), [`line_anywhere.c`](../../src/line_anywhere.c)) calls it with its own, so the compiler builds one loop per rule set with the rules inlined. A file that calls it more than once gets it outlined, with the rules called through pointers, at several times the cost; one call per file keeps it inlined.

Grapheme rules only look back. Others look ahead: word rules WB6, WB7b and WB12 one code point past any Extend, Format and ZWJ; sentence rule SB8 without limit (after an abbreviation's period the sentence goes on when a lowercase letter comes before any other letter, separator or terminator); line rules LB15b, LB15c, LB19a, LB25 and LB28a one or two code points. Since text may arrive in pieces, a lookahead may cross a piece.

A rule that cannot decide answers hold. The engine remembers the boundary's offset and asks the rule set's resolve function about each following code point until it answers join (no boundary after all), break (report the held boundary, then decide about the current code point afresh) or continue (read on). The end of the text breaks a hold. A held boundary never needs buffered text: the rule state remembers what the lookahead has seen, and the offset is all the engine keeps.

Each rule set keeps a few bytes of state beyond the previous code point: whether an odd number of regional indicators precedes, where an emoji ZWJ sequence or a sentence ending stands, the last class other than a space for the "X SP* ×" line rules. The comments at the top of each rule file list what it keeps and why.

## Text in pieces

The cursor ([encoding.md](encoding.md#conversion-and-pieces)) keeps the bytes of a sequence a piece cut off and asks for more text with `muni_needMoreText`. The iterator records that it asked, and a feed is accepted only then: fed earlier, the unread rest of the current piece would be lost. The iterator never keeps a pointer to an earlier piece, so the caller may reuse its buffer.

## Boundaries around an offset

`muniSegmentIterator_FindBreaksAround` ([`src/segment.c`](../../src/segment.c)) answers for one offset without stepping from the start of the text. A segmenter started at some position reads on exactly as one started at the start of the text once its state there is the same, holds included. Each rule file defines a window function (`muniGraphemeWindow` and the others in [`segmenter.h`](../../src/segmenter.h)): given the one or two code points before a position, it says whether they fix every part of the rule set's state that a later decision reads, whatever came before them. A segmenter started fresh at the window's start then reaches the position in the state the whole text gives it.

- Grapheme clusters: one code point, unless it is Extend, ZWJ or InCB=Extend, which carry an emoji sequence or a conjunct linker on, or a regional indicator, which flips the count. A line iterator that breaks anywhere uses the same window.
- Words: two code points, neither skipped by WB4, the second no regional indicator. They are the actual, previous and before classes; a hold can be open only at the second (WB6, WB7b, WB12), and whether it is depends on the two alone.
- Sentences: a paragraph separator, which SB4 breaks after and which ends every SB8 hold and sentence ending; the class before it is read only after an ATerm. Or a terminator, or a terminator and a space, with no Extend or Format before the terminator: a terminator ends any SB8 hold and starts an ending whatever came before, so the ending, whether it began with an ATerm, and the class before (for SB7) are known.
- Lines: a hard break, or two code points of Plain (AL, HL, ID, EB, EM, NU, but not U+25CC, an LB28a aksara) of which the second may be a space. After a hard break only the class before it stays open, and only LB19a, LB20a, LB21a and LB28a read that class, after a quotation mark, hyphen or virama. Two Plain classes fix the previous and before classes, the last class other than SP, the LB25 number state and the regional indicator count, and leave no hold.
- With a word segmenter set, no position between two SA code points: the segmenter answers about the whole run.

The call backs up from the offset one code point at a time, finding code point starts as reading from the start does (any byte other than a continuation byte starts one, and a continuation byte no lead byte reaches is one of its own), until a window fixes the state and there is a boundary at its end. Whether there is one, the engine decides: a segmenter started at the window's start reads a piece that ends after the code point at the position, so it reports the boundary or asks for more text after a few code points, keeping the search linear. From that boundary, or from the start of the text, a segmenter over the rest of the text reports the boundaries up to the first past the offset; those it reports inside the window, from a state the window had not yet fixed, are dropped. A run handed to the word segmenter inside a window may be cut at its start, as a piece boundary may cut one; the boundaries from the window's end on are those of the whole text.

The windows were derived from the rule code, not from the UAX texts, and `test/test_segment.c` checks the call at every offset against stepping from the start: every case of the four conformance files, the cases of each joined into one text, and random texts of their code points, SA text and ill-formed UTF-8, at every kind and setting. Some of the windows' conditions are stricter than the answers need: a window that left the regional indicator count or a sentence ending open would also change the decision at its end, which the boundary check then refuses. They keep each window's claim true, and cost only restart points missed. A window that leaves open what the boundary check cannot see fails that test: an Extend or regional indicator in a word window, an Extend or Format before a sentence terminator, a combining mark in a line window, a position inside an SA run, and a grapheme or line window with no condition at all; so does leaving out the boundary check. `test/fuzz_segment.c` compares the call with the iterator's boundaries for the input's kind, overrides, line settings and breaker.

## Strictness levels

A line iterator breaks at one of the levels of CSS's `line-break` property (CSS Text 3, section 5.2), and the writing system tells it whether the rules CSS keeps for Chinese and Japanese apply. Loose resolves Line_Break=CJ as ID, the tailoring rule LB1 itself allows. Normal and strict keep CJ as NS, as the CSS Text 3 Candidate Recommendation Draft of 14 August 2026 says in section 5.2 ([line-break](https://www.w3.org/TR/2026/CRD-css-text-3-20260814/#line-break-property)): "The following breaks are forbidden for normal and strict line breaking and allowed in loose: breaks before Japanese small kana or the Katakana-Hiragana prolonged sound mark, i.e. characters from the Unicode line breaking class CJ." ICU4C's normal rules and earlier CSS drafts allow CJ breaks in normal, so a comparison with them differs there. The other breaks CSS adds are allowances by code point in [`line_rules.h`](../../src/line_rules.h), not class changes: making a fullwidth prefix an ideograph, for example, would also allow a break before it, which CSS does not. An allowance is checked after the glue of LB11 to LB12a and yields to it, to LB4 to LB10, and to LB14 and LB15a; after a prefix it also yields to LB13. The line rules live in that header, and two files build a loop from them: [`line.c`](../../src/line.c) for the default settings, which are 0, reading no setting (the lookup and the decision take a constant that folds the level's tests away, CJ's class included), and [`line_tailored.c`](../../src/line_tailored.c) with the allowances. `src/segment.c` picks the file once per call. Testing the settings once per code point in a single loop cost the default rules 2% more instructions; with the split they cost 0.15% more than before the levels existed (2.2908 to 2.2941 billion instructions on the bench), the price of picking the loop once per call, and the binary carries the line rules twice.

Anywhere has its own rule file, [`line_anywhere.c`](../../src/line_anywhere.c), which breaks at grapheme cluster boundaries through the grapheme rules of [`grapheme.h`](../../src/grapheme.h) and keeps only LB4 to LB6. `src/segment.c` sends a line iterator there once per call. The grapheme state takes the place of the two code points in the line rule state, which anywhere does not read, so the iterator does not grow.

## Complex-script runs

Thai, Lao, Khmer and Burmese (Line_Break=SA) need a dictionary to break between words. Dictionaries are large (megabytes for the four languages, hundreds of kilobytes for neural models, against tens of kilobytes for all the line breaking rules), so the library carries none and hands each maximal SA run to the caller's breaker ([`src/complex.c`](../../src/complex.c)); without one, the run follows rule LB1. A first-party dictionary could later be an optional component loaded at run time without changing the API.

A run lies within the current piece and starts at an SA code point read whole from it. The breaker is asked for the next break each time the iterator passes the previous one. Its answer is caller input and is clamped: an answer at or before the position asked about, or past the run, means no break inside the run. A break before a combining mark is ignored.

## Class overrides

Locale data such as CLDR changes segmentation in two ways. Suppressions, like the abbreviation lists that keep "Mr." from ending a sentence, only remove boundaries, so a caller filters the boundaries an iterator reports and the library needs nothing. A class change, such as Greek's semicolon as STerm, also adds boundaries, so it has to reach the rules. `muniSegmentIterator_SetBreakClassOverrides` gives a word or sentence iterator a caller-owned table of code points and classes, and the rule file's lookup consults it before the rules see the class.

The table is sorted by code point and checked once when it is set (code points, order, classes), so the lookup is a binary search and a table of any length costs a logarithm per code point, keeping segmentation linear in the text. With no table the lookup skips it. The iterator stores the pointer after the rule state, and the count in the word or sentence rule state, the only kinds that use it. Only the lookup changes: rules that read another property of the code point, such as WB3c's Extended_Pictographic or the Line_Break=SA runs a word iterator hands to a complex breaker, see Unicode's values.

## CLDR root

CLDR's `common/segments/root.xml` writes the same rules as regular expressions, and locale files tailor them. Checked against CLDR 49, its word and sentence rules are UAX #29's. Two rules differ, and the library follows the current UAX in both, since its every answer comes from one Unicode version and the conformance files define them:

- Line breaking, LB12a: root writes `[^ $SP $BA $HY $HH] × $GL`, which allows a break after BA before GL. Unicode 18 keeps BA × GL (`LineBreakTest.txt` has a BA × GL case under rule 12.1).
- Grapheme clusters, GB9c: root still requires a consonant before the linker; Unicode 18 does not (see the trap below).

Elsewhere root takes every class from the Unicode properties, so a difference can only come from the data's Unicode version.

## Script runs

[`src/script_runs.c`](../../src/script_runs.c) keeps, for the current run, the set of scripts every code point in it can belong to, as a 256-bit mask over Script indexes. A code point with a real Script narrows the set to its Script or its Script_Extensions, and the run ends where that would leave no script; Common and Inherited code points leave it alone. Opening brackets remember the run's script on a stack of 32, whose oldest entry drops when it is full; a closing bracket that matches one counts as a code point of that script, so brackets around foreign text land in the script outside. The iterator shares the cursor and the piece protocol with the segmenters.

## Traps

- Word and sentence boundaries are the standard's and do not always fall on grapheme boundaries (U+0600, Prepend and numeric, takes a word boundary after it before punctuation). Do not snap them inside the library; callers that need both snap one to the other.
- GB9c as Unicode 18 defines it joins an InCB linker with the next consonant whether or not a consonant precedes the linker in the cluster; older versions, and ICU builds of them, required one. The ICU fuzz target skips such text.
- The segmentation conformance files run three ways, including fed one byte at a time, which reaches every hold across a piece boundary. A rule change that passes the whole-text run but not the bytewise one keeps state the hold does not carry.
